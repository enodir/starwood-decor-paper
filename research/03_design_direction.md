# STARWOOD — Дизайн-направление (по скиллу frontend-design)

Дата: 2026-07-07
Источник метода: плагин `frontend-design` (SKILL.md) — подход "дизайн-лид небольшой студии", два прохода: brainstorm/plan → критика на клише → build.
Этот документ — Pass 1 (план) + Pass 2 (критика/ревизия). Код не пишем. Результат используется для правки `PRD.md`.

---

## 0. Что этот скилл меняет в подходе

Ключевые требования скилла, которые PRD v1.0 не учитывал:
1. **Заземление в предмете (subject)** — дизайн должен расти из реального мира decor paper/полиграфии (ротогравюрная печать, цилиндры, слои, пропитка, прессование), а не быть нейтральной "корпоративной" оболочкой.
2. **Hero как тезис** — не "заголовок + CTA по центру" по умолчанию (это шаблонный ответ, прямо назван в PRD v1.0 §3.2). Нужен более осмысленный вход.
3. **Явный анти-чек-лист AI-дефолтов**: (а) тёплый кремовый фон + контрастный serif-дисплей + терракотовый акцент, (б) почти-чёрный фон + один яркий акцент, (в) broadsheet-вёрстка с hairline-линиями и нулевым radius. **Риск для STARWOOD: бренд-цвет #845036 — это терракота.** Если добавить кремовый фон и serif — попадаем ровно в клише (а). Это нужно сознательно обойти.
4. **Нумерация оправдана только если реально последовательна.** В PRD производственный процесс (§3.4) — реальная последовательность, значит нумерация здесь легитимна. Но "3 преимущества" (§3.5) — не последовательность, их не нужно нумеровать как 01/02/03 (в текущем PRD это не указано явно, но нужно закрепить).
5. **Один сигнатурный элемент, вокруг него — тишина.** Текущий PRD (§4 motion-таблица) описывает 7 разных анимационных паттернов без единой темы — это "разрозненные эффекты", именно то, от чего скилл предостерегает.
6. **Копирайтинг — часть дизайна**, не нейтральная заливка текста.

## 1. Pass 1 — Черновой дизайн-план

### 1.1 Предмет, аудитория, единственная задача страницы
- **Предмет:** декоративная бумага — тонкий печатный лист, который после пропитки смолой и прессования становится лицевой стороной мебельной плиты. Мир предмета: рулоны бумаги, ротогравюрные цилиндры, цветоделение (4-8 проходов краски), пропитка смолой (прозрачность/блеск), пресс (тепло + давление), готовая плита.
- **Аудитория:** технолог/закупщик мебельного или напольного производства — уже определено в PRD §2.
- **Единственная задача страницы:** доказать техническую компетентность завода за 60-90 секунд и довести до заявки "Запросить образец".

### 1.2 Цвет (4-6 именованных hex)
Бренд-цвет `#845036` зафиксирован брифом — не меняется. Но его нельзя класть на кремовый фон с serif — это клише (а). Вместо этого строим палитру вокруг **типографской печати**, где `#845036` читается как цвет крафт-бумаги/дерева, а не "модный терракот":

| Токен | HEX | Роль | Обоснование из предмета |
|---|---|---|---|
| `--press-black` | `#1E1A17` | Основной тёмный фон (hero, footer, process) | Цвет печатного цеха/машин, не "дефолтный near-black для эффекта" — тематически цвет ротогравюрной печати и вальцов |
| `--kraft-brown` | `#845036` | Бренд-акцент (CTA, ключевые акценты, брендовые блоки) | Заданный бренд-цвет = цвет крафт-бумаги/декора дерева |
| `--raw-pulp` | `#E8E4DC` | Светлый фон для контентных секций (не кремовый F4F1EA!) | Цвет неотбелённой бумажной массы — серее и холоднее клишированного "тёплого крема" |
| `--registration-cyan` | `#1C8CA0` | Второй, "рабочий" акцент: интерактивные состояния, метки, hover | Циан — один из 4 цветов CMYK-печати; в ротогравюре именно циан используется как первая контрольная метка при совмещении цветов |
| `--ink-grey` | `#4A433C` | Текст на светлом фоне | Тёплый тёмно-серый — "цвет типографской краски", не чистый чёрный |
| `--pulp-white` | `#F7F5F1` | Карточки/поверхности поверх raw-pulp | Лёгкий разбел для создания глубины внутри светлых секций |

**Почему это не клише:** нет кремового фона в паре с serif (клише а); тёмный фон не единственный и не с одним ярким акцентом — есть светлые секции + два разных по природе акцента (брендовый брутто-коричневый и "рабочий" циан) (уход от клише б); hairline-линии используются точечно как деталь (см. 1.4), а не как основа всей вёрстки (уход от клише в).

### 1.3 Типографика (2-3 роли)
Не берём "контрастный serif-дисплей" (это прямой путь в клише а). Вместо этого — шрифты из мира инженерной/промышленной печати:

- **Display (заголовки):** **PT Sans Narrow** (ParaType) — узкий, плотный, утилитарный гротеск от российского типографического бюро. При реализации выяснилось, что изначально рассмотренный Big Shoulders не поддерживает кириллицу (только latin/vietnamese) — неприемлемо для RU-контента. PT Sans Narrow не только решает эту проблему, но и усиливает замысел: шрифт, спроектированный в России для узких табличных/технических надписей, ближе к "промышленной маркировке", чем американский декоративный аналог. Используется крупно, с плотным трекингом, иногда capslock для ключевых тезисов.
- **Body (основной текст):** **IBM Plex Sans** — нейтральный, читаемый, с инженерным происхождением (создан для IBM как "рабочий" шрифт техпродукции) — концептуально подходит заводу лучше, чем Inter/Helvetica-дефолт.
- **Utility/mono (коды декоров, номера партий, метки стадий процесса, подписи к сертификатам):** **IBM Plex Mono** — используется для всего, что выглядит как техническая маркировка: код декора ("WD-114"), номер стадии производства, регистрационные метки. Это прямая отсылка к маркировке на печатном листе.

### 1.4 Layout-концепция + сигнатурный элемент

**Сигнатурный элемент: "Слоёный пресс" (The Layer Press).**
Единственный по-настоящему запоминающийся момент дизайна: визуальная метафора реального продукта — крафт-бумага + печатный декор-слой + смоляной overlay складываются друг на друга и "спрессовываются" в единую плиту. Это не абстрактная анимация ради красоты — это буквально то, что происходит на заводе. Используется в **трёх** местах, и больше нигде (дисциплина "спрессовать боль в одном месте"):
1. **Hero** — при загрузке страницы слои (текстурный крафт-лист → печатный декор → глянцевый overlay) сходятся и накладываются друг на друга за ~1.2s, оставляя финальную "плиту" как фоновый визуал рядом с заголовком.
2. **Секция "Производственный процесс"** — тот же слоёный стек проходит стадии по мере скролла (pinned), это оправданная последовательность (сырьё → печать → пропитка → прессование), поэтому нумерация стадий (01-05 в mono-шрифте) здесь легитимна по правилам скилла.
3. **Карточка декора (hover)** — верхний правый угол карточки "приподнимается", как уголок бумажного листа, показывая слой текстуры под ним (не абстрактный zoom, а буквально "заглянуть под верхний слой").

Всё остальное в дизайне — **тихое и дисциплинированное**: без параллаксов "для красоты", без множества разных transition-стилей между секциями (это исправляет motion-таблицу PRD §4, где было 7 разных анимаций без единой темы).

**Вторичное структурное устройство — "регистрационная метка" (registration mark).**
В ротогравюрной печати совмещение цветов проверяется маленькими crosshair-метками + цветовыми точками (C/M/Y/K) по краям листа. Берём это как тихий, повторяющийся визуальный девайс:
- Маленький crosshair + mono-подпись в левом верхнем углу каждой секции вместо "generic eyebrow label" — например `+ PASS 03 — ПРОПИТКА` для секции процесса, `+ КОЛЛЕКЦИЯ — ДЕРЕВО` для каталога декоров.
- Тот же crosshair используется как маркер "активного" фильтра в каталоге декоров.
- Это не декорация — это структурное обозначение "здесь начинается новый блок", заимствованное из реального языка предмета (печатной регистрации), что отвечает принципу "structure is information".

**Футер как колофон (colophon).**
В печатной индустрии колофон — блок в конце издания с информацией о печати: тираж, бумага, типография. Вместо стандартного "О компании / Навигация / Контакты" в три колонки, футер стилизуется как колофон печатного листа: моноширинным шрифтом на `--press-black` фоне —
```
STARWOOD DECOR PAPER — REGISTRATION No. 2026
Отпечатано на … | Плотность … г/м² | Коллекций в каталоге: …
Производство: [город] | Экспорт: [регионы]
```
— с обычными ссылками (контакты, соцсети, копирайт) ниже как менее акцентная часть. Это придаёт футеру индивидуальность вместо generic "3 колонки", и опять же взято из реального мира предмета, а не придумано абстрактно.

## 2. Pass 2 — Критика против AI-дефолтов

Проверка по трём клише, названным в скилле:

1. **"Тёплый крем + контрастный serif + терракот"** — НЕ используем: фон светлых секций `--raw-pulp` (#E8E4DC) холоднее и серее кремового, display-шрифт — узкий индустриальный гротеск (PT Sans Narrow), а не serif. Терракотовый `--kraft-brown` — оставлен только потому что задан брифом (бренд-цвет), но не является доминирующим фоном — используется точечно как акцент (CTA, брендовые блоки). Совпадение с клише отсутствует по 2 из 3 признаков намеренно.
2. **"Почти-чёрный фон + один яркий акцент"** — НЕ используем как основу всей страницы: `--press-black` применяется только в hero/process/footer, не по всей странице; акцентов два разных по функции (`--kraft-brown` для бренда/CTA, `--registration-cyan` для интерактивных/рабочих меток) — не "один яркий акцент для всего".
3. **"Broadsheet с hairline-линиями и нулевым radius"** — hairline и crosshair-метки используются только как деталь регистрационных меток по краям секций, а не как принцип всей сетки; карточки декоров и CTA-кнопки не обязаны иметь нулевой radius (решается на этапе визуального дизайна, вероятно небольшой radius для карточек, острые углы только для "печатных" элементов типа crosshair/метки — сознательное разделение).

**Проверка "структура = информация":**
- Нумерация 01-05 оставлена только в разделе "Производственный процесс" (реальная последовательность) — из PRD §3.4.
- В разделе "Преимущества" (PRD §3.5) нумерация **не используется** (это не последовательность), вместо неё — просто карточки с иконкой; это отличие от исходного PRD, где нумерация не была явно исключена.

**Проверка "один сигнатурный момент, вокруг тишина":**
- Из мотион-таблицы PRD v1.0 §4 (7 разных паттернов) выделяем "Слоёный пресс" как единственный сигнатурный, используемый в 3 логически связанных местах (hero/process/decor-card hover) — это один мотив, а не 7 разных.
- Остальные анимации из PRD v1.0 (progressive reveal, grayscale→color логотипов, kinetic counters) остаются, но переклассифицируются как "тихая" фоновая механика — не претендуют на "вау", не конкурируют с сигнатурой.

## 3. Что это меняет в PRD (сводка правок, применены в PRD.md)

1. Добавлена секция "Дизайн-система" с палитрой/типографикой из §1.2-1.3 этого документа.
2. Hero (§3.2 PRD) переписан: асимметричный layout вместо центрированного, сигнатурная анимация "слоёный пресс" вместо обобщённого "каскадного появления + parallax".
3. Производственный процесс (§3.4 PRD): визуальный движок явно = слоёный стек + нумерация обоснована.
4. Преимущества (§3.5 PRD): явно исключена нумерация 01/02/03.
5. Карточки декоров (§3.3 PRD): hover-эффект заменён с "texture zoom" на "приподнятый уголок" (тот же сигнатурный слоёный мотив, а не отдельный эффект).
6. Motion-таблица (§4 PRD) реструктурирована: один сигнатурный паттерн + отдельно перечислены "тихие" фоновые эффекты, чтобы не выглядеть как список из 7 несвязанных анимаций.
7. Футер (§3.10 PRD) переопределён как колофон вместо стандартных 3 колонок.
8. Добавлено требование "eyebrow-labels" в стиле регистрационных меток (`+ PASS 0X — …`) как замена generic-заголовков секций.
